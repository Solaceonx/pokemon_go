# Battle video screen reader

Imports battle footage, proposes individual battles, reads every decoded frame and
shows saved readings beside the video in a local viewer with a live values table.
The decision logic remains in the repository's existing `pogo/` package.

## Windows: start without commands

1. Install Python 3.12 from [python.org](https://www.python.org/downloads/) if needed.
2. Double-click **Setup on Windows.cmd** once to install the reader's dependencies.
3. Double-click **Open Battle Viewer.cmd**. An empty checkout opens an empty viewer;
   use **Open battles folder** to select existing local clips.
4. Double-click **Import Battle Video.cmd** to paste a YouTube video or Twitch VOD
   link. Existing originals and valid analysis are reused. Choose a calibrated
   layout for a new recording.

The included profiles match the selected Reis2TheOccasion iPhone recording and
HomeSliceHenry Android recording. A creator name alone does not identify a layout.
Twitch intake is implemented but has not been checked against a specific VOD.
The downloader may need updating when a platform changes. Merging/post-processing
formats can require FFmpeg; some YouTube formats need a supported JavaScript runtime.
Downloaded executables and models are not committed to Git.

On another OS, create a Python environment, install `requirements.txt` and run
`python launch_viewer.py`. Run scripts from this directory.

## What is read

- Active displayed species names and CP; forms/shadow status remain unresolved.
- Visible health-bar pixels and settled fraction ranges. Whole-number HP requires
  a verified maximum; species and CP alone do not establish it.
- Shield and party markers, charge-button positions/visual readiness, switch and
  replacement cards, readable move/effect text and supported scene cues.
- Separate causal scene estimates, with inference and stale OCR clearly marked.

Every-frame decoding is not complete game-state recognition. Animated/hidden
values remain unknown. Continuous health reconstruction, numerical energy,
switch-clock measurement, all minigame types and live iPhone control are unfinished.
Reviewed observations can be exported with `export_tracker.py` using the contract
in [`../docs/agent_instructions.md`](../docs/agent_instructions.md).

## Local data and reproducibility

Videos, `battles/`, `sources/`, downloaded `tools/`, generated HTML and local
analysis/evaluation files are ignored by Git. Raw readings are compressed;
refinements are recorded separately. Prior analysis is archived without copying
the videos. The reader uses shared `../data/gamemaster.json`.

The historical local library has 18 battles and 56,704 frames: nine Reis development
clips and nine Henry exposed regression clips, split by source. Both videos were
inspected during development, so this is not an untouched accuracy benchmark.
The historical manifests reference media kept locally; `verify` requires those
exact bytes. Rebuilt videos need a rebuilt manifest before evaluation.

`dataset/baseline-summary.json` records historical checks and measured storage:
about 22 MB video plus 0.56 MB saved files per average 114-second battle. A three-
minute battle projects to about 35 MB video plus 0.9 MB saved files. Originals,
shared tools and prior analysis versions are additional storage. Recognition
accuracy requires independent labels; the Henry human benchmark has none yet.

`dataset/reader-snapshots/` preserves historical reader versions and fingerprints.
The repository integration adds portable launchers and shared-data lookup;
current predictions therefore get new code fingerprints. The historical packages
are not asserted to have been generated by this integrated version.

Only selected phone-crop test images are included. `image_fixtures.py` restores
the original image geometry with black padding outside the gameplay viewport;
the detector's input pixels inside the viewport are preserved exactly. Hashes are
in `fixtures/test-images.json`. No complete recordings or frame-by-frame dumps
are uploaded.

## Developer commands

```text
python -m unittest discover -s . -p "test_*.py"
python run_video_pipeline.py https://youtu.be/qSaL7jM9NbA --download --stage track
python refine_saved_readings.py
python storage_report.py
python build_lazy_viewer.py
python validate_library.py
python dataset_tools.py build
python dataset_tools.py verify
python dataset_tools.py evaluate --partition train --labels fixtures/reis-phase-labels-01.jsonl
```

The interactive importer also performs refinement and viewer rebuilding. A new
source needs an explicit profile and dataset partition policy. Full processing is
an offline job and can take hours; the alternate ROI reader has no established
real-time guarantee. See [`PIPELINE.md`](PIPELINE.md) and
[`dataset/README.md`](dataset/README.md) for the development history and limits.
