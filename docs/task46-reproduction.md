# Reproducing creator-footage results

The installed 82-record collection was generated by **v21g2**. The current stable reader is **v21h2**, which adds exact-frame caption timing and fixes Windows cache-backup paths. Each version has a separate source bundle and measured report; existing data does not inherit a newer reader's verification.

The records are under `games/creators/<channel>/<source>-<number>/`. `source.json` identifies the public source, cut boundaries, viewport and video hash. Repeated state streams are compressed JSON Lines. `game.txt` is a rendering of the typed `game.json` record. Videos, frame images, unrestricted OCR and in-game trainer names are excluded from Git. The incomplete Henry `2904735277-010` record is excluded from this batch.

## Check the checkout

```text
python -m unittest discover tests
python scripts/check_pvpoke.py
python scripts/index_games.py --check
```

The stable checkpoint passes 646 tests with one existing skip and reproduces all 108 reference simulator battles. See `runs/task46-installed-v21g2.json` for installed file hashes, privacy/protection checks, generation versions and retained failures.

## Recover exact source bytes

Git can convert source-code newlines during checkout. The small source bundles retain the exact UTF-8 bytes used for the processing fingerprints:

```text
python scripts/recording/source_snapshot.py verify runs/task46-source-v21g2.json.gz
python scripts/recording/source_snapshot.py extract runs/task46-source-v21g2.json.gz --destination .vod/recovered-v21g2-source
```

Extraction requires a new destination and verifies paths, duplicate entries and hashes. A bundle contains the files in its manifest; it is not a standalone installation. Use those files with a separate copy of this checkout, its GameMaster data, the configured local screen reader and matching private inputs. Preserve the active working copy while a replay is running. Older and failed experimental versions have separate bundles and reports.

Creator records, frozen references and Task46 reports use `-text` Git attributes so checkout preserves their bytes. Compressed streams also remain byte-exact. This keeps source-reference and prediction hashes meaningful across systems.

## Replay matching private cuts

On a configured checkout with the matching local cuts and cached readings:

```text
python scripts/recording/replay_creators.py --work .vod/replay-check --channel homeslicehenry --skip-index
```

The existing replay command checks source hashes, saves previous exports and records resumable checkpoints. Use a separate work directory for each channel and at most three workers. Finish every channel before rebuilding the catalog with `python scripts/index_games.py`. Saved originals and cut videos are retained locally; experimental copies share video files instead of duplicating them.

## Interpret the results

`runs/task46-fullstate-state-v21g2-all82.json` compares all 82 records: 29 strict consistency passes, versus 27 in the preceding complete replay and 17 initially. Three failures became passes and one previous pass now fails an energy check. That regression remains unresolved.

Consistency is separate from source accuracy. The source-reviewed development reports retain event precision/recall, timing uncertainty, field coverage, reference corrections and battle-level margins. The 30 development battles have matching event counts; only 20 pass the stricter timing gate. These are tuned examples, not an untouched test. Health is a measured fraction interval; maximum HP, hidden energy and unknown state are not supplied from a default build.

Run `scripts/recording/state_readiness.py` with a source-event evaluation report to bind verification to the exact exported hashes. A report from another replay cannot certify changed files. Full-state certification remains zero: continuous health, useful energy, stat stages, switch clocks and another untouched source evaluation still need work. See `docs/task46-fullstate-validation.md` and the dated entries in `docs/status.md`.
